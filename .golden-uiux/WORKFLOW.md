# Golden UI/UX everyday workflow

Use this workflow proportionately. The user’s normal task prompt is the task brief; do not require the user to choose pattern IDs, skills, CSS values or routine implementation details.

## Authority and project context

1. Follow binding security, privacy, legal, data-integrity and accessibility requirements first. Preserve the separate Golden Agentic Engineering Standard and all project-level engineering policies.
2. Inspect the project’s own approved profile, instructions, design-system conventions, components, data/API contracts and relevant tests. A project adapter governs approved product identity, components, typography, density and layout choices. Universal Golden patterns guide unresolved behavior; they do not replace a project’s approved choices.
3. A profile marked PROPOSED, an observed source value, an installed skill, or an agent-generated statement is not an approval or permission grant. User instructions and repository protections define the authorized change scope.

## Everyday implementation

1. Understand the user, task and complete workflow. Read the smallest relevant set of source and project convention files.
2. For meaningful UI work, describe the task as structured intent (workflow steps, component needs and constraints) and run the local route command. Let it select applicable contracts. Read only the routed pattern and skill bodies; do not manually work through all 14 patterns.
3. For a substantial new workflow or a design decision that benefits from an isolated comparison, use `design-session start`. It creates an immutable baseline and a candidate folder. Implement in the candidate, then run its relevant tests and `design-session finish`. For a small fix or a normal authorized feature request, work in the requested project scope; do not force a design competition.
4. Make the real interface change. Preserve the application’s own data, API behavior, visual identity and component conventions. Do not stop at a direction record or mockup when the user asked for working UI.
5. Run focused checks first. Invoke applicable gates:
   - **G1_DATA_TRUTH** — displayed records and details match their verified source.
   - **G2_API_CONTRACT** — requests, permissions and response shapes match the real contract.
   - **G3_ACCESSIBILITY** — semantics, accessible names, keyboard operation and visible focus.
   - **G4_RENDERED_CONTRAST** — measured rendered text/state contrast, not guessed CSS values.
   - **G5_ELEMENT_GEOMETRY** — element-level geometry, overflow, clipping and responsive behavior.
   - **G6_EVIDENCE_AND_RULE_DELIVERY** — source-bound evidence and trustworthy delivery context. Local files alone do not authenticate delivery.
6. Use the actual rendered app and authorized browser tools for visual inspection when available. Fix observed defects and rerun affected checks. If rendering or authenticated skill delivery is unavailable, report **NOT_RUN** or **UNKNOWN**; never infer PASS.
7. Report the exact files changed, commands/results, remaining risks and unverified claims. Ordinary visual work does not need a benchmark, an exhaustive comparison, extra agents or a second owner decision unless the task or a binding policy requires one.

## Local command entry points

After project-local installation, the offline CLI lives at `.golden-uiux/uiux.py` and can be run with Python 3.10 or newer:

```sh
python3 -B .golden-uiux/uiux.py patterns
python3 -B .golden-uiux/uiux.py pattern P02
python3 -B .golden-uiux/uiux.py profile .golden-uiux/everyday_project_profile.json
```

A structured route can be generated by the agent from the task and source inspection:

```sh
python3 -B .golden-uiux/uiux.py route "Find an asset, inspect its identity and return to the filtered grid" \
  --profile .golden-uiux/everyday_project_profile.json \
  --intent-spec /tmp/golden-intent.json
```

For a source-bound isolated workflow, the agent prepares request JSON from the exact relevant files and starts:

```sh
python3 -B .golden-uiux/uiux.py design-session start /tmp/golden-request.json \
  --source-root . --output /tmp/golden-session
```

After implementing in that session’s `candidate/` folder:

```sh
python3 -B .golden-uiux/uiux.py design-session finish /tmp/golden-session \
  --submission /tmp/golden-session/submission.json
```

The session finish command dispatches registered validators; it does not approve a profile, authenticate the client, or certify visual quality.
