# Browser evidence collector — use only on an authorized non-production UI

`python3 uiux.py browser <spec.json> --output <evidence-directory>` performs **passive-by-default but not intrinsically read-only** Chromium/Playwright navigation **when** the tested app is reachable from that workstation. It will not start the app, alter source, authorize baselines or mark release PASS. The sample `examples/browser_audit_LOCAL_ONLY.json` has a loopback URL and placeholder source/profile identity; replace values after owner approval. Loading pages can execute JavaScript and even HTTP GET requests may change badly implemented applications. **Do not run against production or sensitive data**. By default `base_url` and every `allowed_origins` entry must be loopback (`localhost`, `127.0.0.1`, `::1`), and the browser permits only GET/HEAD/OPTIONS, passive assertions, and no WebSockets (fail closed if interception is unavailable) or service workers. A blocked mutating request is a probe failure, not a successful observation.

**Explicit risk gates:** `--allow-remote` opts in to remote origins (still restricted to the declared allowlist). `--allow-interactions` opts in to click/fill/press, which may modify DOM or trigger state-changing GET handlers. `--allow-writes` separately allows mutating HTTP requests and requires `--allow-interactions`. Both require a separately authorized disposable test application and test data. No flag provides a guarantee of no side effects. External authorization remains required. The browser collector NEVER represents itself as a safe read-only inspector or as an independently trusted test runner.

**Coverage:** page load/wait, click/fill/press and expected text/value/visibility, bounding rectangles, declared clipping checks, document horizontal overflow, text/background contrast for simple opaque CSS colors, focus sequence, screenshots and optional pixel-diff against an *already approved* local image and its expected SHA-256 digest. A baseline inside the evidence-output directory is rejected to prevent accidental self-comparison. Results are source-declared, not cryptographically tied to Git; they are for independent review.

**Known limitations:** inherited complex blended backgrounds, gradients and transparent colors are UNKNOWN, not PASS; not a general WCAG scanner; no comprehensive label/focus/ARIA semantics, automated axe, human AT, performance trace, network mocking or full visual intelligence. Pixel screenshot diff is noisy across fonts/browsers and cannot determine subjective quality. DOM clipping only catches the declared measured selectors plus document overflow; specialized canvas/SVG 3D requires separate project checks.

**Offline provisioning:** core Python tools require no pip. Browser auditing requires local compatible Playwright Python + Chromium; screenshot pixel diff also requires Pillow. SysGrid already declares `@playwright/test` in `frontend/package.json`; its established Node/Playwright app E2E/CI suite should be preferred for deep app flows and may export evidence using an approved adapter. Do not add a second mandatory browser stack unnecessarily.

**Baseline:** never compare a candidate screenshot against a baseline created from the same candidate and claim regression success. Approval of a baseline is external to this tool. Without an approved baseline, the report explicitly says `NOT_RUN_NO_APPROVED_BASELINE`. An automated capture without independent review does not complete G4/G6.

**WebSocket fail-closed behavior (v0.2.3):** `route_web_socket` must exist and register its denial handler before the browser creates a page. Unsupported Playwright versions, missing APIs or handler-install failures cause a `BLOCKED` route and an overall `BLOCKED` run. Report metadata describes the unavailable capability; it must not report sockets `BLOCKED` without installation. This protection is not a replacement for network sandboxing.

**Measured vertical clipping (v0.2.3):** For each declared `measure` selector, report `scrollHeight`, `clientHeight`, and computed `overflowY`. If content exceeds height tolerance and CSS `overflow-y` is `hidden`/`clip`, flag `vertical clipped content`. A deliberately scrollable region (`auto`/`scroll`) is not a failure unless its label is explicitly listed in `forbid_internal_vertical_overflow`. This is a *targeted measured-element check*, not comprehensive visibility analysis of every nested descendant. Natural document vertical scrolling is not a failure.

## Portability and negative-gate requirement (v0.2.3)

Browser fixture tests in `tests/test_browser_evidence.py` are **optional in the portable unittest suite**. If compatible Chromium or early WebSocket interception is unavailable, these tests show `skipped` with a concrete reason. The suite MUST NOT be reported as 'all browser tests passed' in that case. Package/unit tests can still pass when the browser gate is blocked; this is intentional separation of concerns, not a waiver.

Run `python3 devtools/browser_capability_gate.py --output <approved-evidence-dir>` on the target machine. This command is **mandatory wherever browser verification is required** and returns `3` when the browser is unavailable, `0` only when it actually collects the controlled fixture evidence. It does not test SysGrid or approve production. Avoid network/browser downloads in the intranet: provision approved browser binaries and Playwright from your approved offline source first.

Unsafe screenshot self-baselines (stored beneath the same writable evidence output directory, with missing or mismatched digest) are rejected **before** Playwright import and browser launch. Their results are reported deterministically in `report.json` even on a browserless machine. Baseline approval is still external.
